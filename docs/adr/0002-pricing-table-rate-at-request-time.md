# Pricing Table is versioned; cost is locked to the rate at request time

Provider $/token rates change over time, and no pricing data exists in this codebase today. We considered computing cost live at query time from a single current-rate table, but that would make historical cost figures silently shift retroactively whenever a rate changed — a bill for last month would read differently today than it did last month. Instead, the Pricing Table is versioned with an `effective_from` date per model, and the proxy resolves the rate active at the moment of the request, writing the computed cost directly onto the `usage_log` row. Historical cost is then immutable: it reflects the rate that was actually in effect when the request happened, not whatever rate is active when a report is later run.
