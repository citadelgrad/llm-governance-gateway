# Dashboard mounts on the public proxy, not a separate internal service

Per `docs/architecture.md`, the proxy is the one public-internet-facing service; governance, OPA, Postgres, and Redis all stay internal. The new usage dashboard is an authenticated HTML admin surface, which could instead have been built as a separate internal-only service, matching that pattern. We chose to mount it as new routes on the existing proxy app instead: it reuses proxy's existing auth (API key/JWT) and has direct access to `usage_log`, with no new network hop, no new deployment unit, and no new port. The trade-off is that an admin/cost surface now lives on the same public-facing service as client request traffic, rather than being kept off the internet entirely the way governance and OPA are. This is deliberate — access control is enforced by the existing `admin` role and tenant scoping (see Usage Visibility in CONTEXT.md), not by network placement.
